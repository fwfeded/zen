# 更新与安装校验

[返回首页](../README.md)

## 正常更新

打开 **设置 → 版本更新**。自动检查默认开启，在返回禅后延迟触发，每 24 小时最多一次。失败同样计入间隔，避免离线时反复请求；手动“检查更新”不受此间隔限制。

发现新版后依次点击下载、安装。首次安装来源授权可能需要你在系统设置允许后返回，再次点安装。不会静默替换应用，也不会自动下载大文件。

0.5.5 内置更新地址。旧版第一次可以填入下列地址；明确清空或自定义过地址的用户不会被自动覆盖：

```text
https://github.com/fwfeded/zen/releases/latest/download/latest.json
```

## 官方发布文件

| 文件 | 用途 |
| --- | --- |
| `zen-32.apk` | 0.5.7（versionCode 32）的安装包 |
| `latest.json` | 应用读取的版本、下载地址、大小、SHA-256 与更新说明 |
| `SHA256SUMS.txt` | APK 和版本清单的文件校验值 |

本次不发布主题卡。当前版本的 Source code 压缩包包含对应源码，不能直接安装；手机应下载 APK。历史 v0.5.5 标签创建时仅有文档，详情见项目状态。

## 校验与签名

下载仅允许 HTTPS，重定向仍须为 HTTPS；清单上限 64 KiB、APK 上限 120 MiB。文件大小、SHA-256、包名、递增版本和签名都通过后才能进入安装流程。

包名：`dev.zen.launcher`

当前个人测试渠道签名证书 SHA-256：

```text
b5c8d9d5636fa2a5dc18ce91708e3dc1d4d8e25087e1aac69b39ca005c7c220e
```

为兼容已有安装，0.5.5 沿用原个人测试签名；这不是应用商店正式发行签名。私钥不在仓库和发布附件中。将来正式发行前需要另行规划签名迁移，不能随意换钥后声称可直接覆盖旧版。

SHA-256 用于核对文件完整性，不能单独代替来源信任。只从本仓库的 Releases 下载，不使用别人给出的同名 APK。具备 Android SDK 的用户可用 `apksigner verify --print-certs` 检查证书。

## 更新失败时

- 网络不可达：稍后手动检查，或在浏览器打开官方 Releases 下载；GitHub 在不同网络下的可达性有差异。
- 校验、版本或签名不符：停止安装，重新从官方地址获取并反馈错误，避免先卸载导致记录丢失。
- 系统不允许安装：检查是否只为禅开启了安装来源授权；具体界面由手机厂商决定。
- 覆盖后异常：保留错误提示和复现路径，先反馈。降低清单中的版本号不会让已安装手机自动降级。

## 发布策略

每版增加 versionCode；APK 使用带版本标签的固定地址，不覆盖已发布的同版文件。附件齐备并校验后才发布，固定清单入口指向最新的正式 Release。应用仍属个人测试阶段，“正式 Release”仅指 GitHub 分发标签，不代表所有机型已经完成验收。
